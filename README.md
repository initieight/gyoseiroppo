# 行政六法

行政書士試験の過去問（令和2〜令和7年）から根拠条文を割り当て、「この条文は何年度の何問で問われたか」を条文ごとに表示する無料Web六法です。

公開中：https://gyoseiroppo.com

![トップページ](docs/screenshots/top.jpg)

---

## 解決したい課題

市販の六法は条文を読むためのもので、「その条文が試験でどう問われたか」は載っていません。逆に過去問集は問題単位で並んでいるため、条文側から「ここは頻出か、まだ出ていないか」を引くことができません。

受験者は条文と過去問を頭の中で突き合わせる必要があり、どこから手をつけるかの判断に時間を取られます。

このサイトは過去問を**選択肢単位**で読んで根拠条文を割り当て、条文本文の横に出題年度・問題番号・出題箇所を並べました。条文側から出題実績を引けるようにしたのが中心的な機能です。

## 規模

`npm run validate-data` および `npm run build` の出力から確認できる数字です。

| 項目 | 数 |
|---|---|
| 収録法令 | 11法令 |
| 収録条文 | 3,357条 |
| 出題実績のある条文 | 491条 |

収録法令：憲法／行政手続法／行政不服審査法／行政事件訴訟法／国家賠償法／行政代執行法／国家行政組織法／地方自治法／民法／商法／会社法

条文データは e-Gov法令APIから取得しています（`scripts/fetch_laws.py`）。

## 画面

### 条文ページ

条文本文に加えて、出題回数・出題年度・問題番号、そして条文のどの部分が問われたかを表示します。集計方法と「独自集計であり公式の発表ではない」旨を各ページに明記しています。

![条文ページ](docs/screenshots/article.jpg)

### 出題ランキング

法令ごとに、根拠条文になった問題数で条文を並べます。同数のときは正解肢の根拠になった数、次に問われた選択肢の数で順位をつけています。

![出題ランキング](docs/screenshots/ranking.jpg)

## 担当範囲

個人で以下すべてを担当しています。

- **企画** — 「条文側から過去問を引く」という切り口の設定、収録法令と対象年度の決定
- **データ設計** — 条文JSONと出題データ（`public/laws/` 11件、`public/highlights/` 15件）のスキーマ設計。条文キーの表記（`36の2` のような枝番、`771:787` のような削除条文の範囲）の定義
- **AIを使った実装** — 下記「AIの使い方」を参照
- **データ検証** — 検査スクリプトの設計と、判定が割れた箇所の最終判断
- **SEO設計** — 静的生成の担保、サイトマップ分割、`robots.ts` での生データJSONの除外、統合済み旧URLの301リダイレクト、canonical / OGP
- **公開・改善** — Vercelへの公開、以後の継続的な修正

### SEO設計で実際にやったこと

- 出題実績のある条文とない条文で `sitemap-asked.xml` / `sitemap-unasked.xml` を分割し、インデックス状況を切り分けて診断できるようにした
- サイトマップをISRにすると Vercel のサーバーレス関数上で再生成され、`public/` が同梱されず条文データを読めないまま**3,343件が17件に縮む**事故を起こしたため、`force-static` を明示して固定した（`app/sitemap.ts` にコメントとして経緯を残しています）
- 上記が再発したら出荷前に落ちるよう、ビルド成果物を検査する `scripts/check-build.mjs` を `npm run build` に組み込んだ
- 生データJSON（`/laws/` `/highlights/`）は検索結果に出さないよう `robots.ts` で除外。一方、統合した旧URLは noindex を読ませる必要があるため、あえて robots でブロックせず301で寄せている

## AIの使い方

実装の大部分は Claude Code で書いています。45コミット中32コミットに Claude の `Co-Authored-By` が入っています。

使い方は「AIに判断させる」のではなく、**役割を分けて、判断は人間が持つ**という形に寄せています。

### AIに任せていること

- 実装（コンポーネント、ルーティング、データ加工スクリプト、検査スクリプト）
- 大量データの機械的な処理 — 過去問を選択肢単位に分解し、条文候補を抽出する
- パターン抽出と一括修正
- 別モデルへの**独立判定**。`tools/make_blind_review.mjs` は、こちらの割当を一切見せずに設問文と選択肢だけを渡して白紙から根拠条文を答えさせる入力を作ります。正解が確定している対照群を混ぜて相手の精度自体を測り、`tools/compare_blind_review.mjs` で突合CSVを出します

### 人間がやっていること

仕様決定、レビュー、検証、そして**採否判断**は人間側で持っています。

条文の割当は法解釈を含むため、AIの出力をそのまま採用していません。実際にリポジトリ側もその前提で組んであります。

- `tools/authoritative.json` — 運営者本人が過去問を逐条分析した結果。機械的な抽出や別モデルの独立判定より**上位**に置き、該当する問題の割当を丸ごと置き換えます
- `tools/overrides.json` — 機械的な補正では正しく決まらなかった割当を手で上書きする層。判例のみが根拠で条文を特定できない選択肢は `null` にして集計から外し、判断の出所を `source` に残します
- 未検証のものは未検証と書く — 他資格（司法試験・予備試験・司法書士・宅建）の出題実績は行政書士分と違って独立判定を通していないため、行政書士の数字と合算せず、表示時に未検証である旨を明示する方針をコード上のコメントとして固定しています

### 検証の仕組み

`npm run validate-data` は条文データと出題データの整合性を10項目検査します。ERRORが1件でもあれば exit 1 になります。

1. 法律マスタと実ファイルの対応（欠落・余剰）
2. `lawId` フィールドとファイル名の不一致
3. 条文キーの重複・形式不正
4. 条番号の欠番
5. 存在しない条文への出題データ参照（dangling reference）
6. `count` と `years` の整合
7. 問題番号の形式ゆれ
8. 年度ラベルの形式ゆれ
9. 本文が空 / タイトル欠落
10. ハイライト文字列が本文に存在しない

これに加えて、同一の出題データを複数条文が持っている場合（論点ブロック単位で加算された疑い）をWARNとして出します。WARNは自動修正せず、人間が中身を見て判断する対象として残しています。

## このリポジトリについて

- **個人制作物です。** 受託案件ではなく、企画から公開・運用まで個人で行っているものです。
- **法律相談を行うサイトではありません。** 条文本文と、過去問の出題実績を表示するだけのものです。個別の法律相談や法的助言は扱いません。
- 出題実績の集計は**独自集計であり、試験実施機関による公式の発表ではありません。** 過去問を選択肢単位で読んで根拠条文を割り当てているため、1問で複数の条文にカウントが入ります。
- 条文本文は e-Gov法令API から取得したものです。
